#### Anti-Patterns Verdict

**LLM assessment**: 整体是可用的产品工具壳，不是营销落地页。风险点：Fraunces 已被 detector 标为 overused；暖亮底+金字接近「日光手帐」边缘；`shell-in`/`editor-in` 整页入场不符合 product register「不做编排式进场」。选中态已改为洗底+hairline，方向正确。

**Deterministic scan**: 2 warnings on `index.html`

- `overused-font`：Google Fonts Fraunces
- `single-font`：detector 误报（页面实际还有 Source Sans 3 / Noto；仅从 link 行误判）→ **false positive**

**Visual overlays**: 未注入。dev server 未运行；无 browser mutation 路径。Fallback：源码审查 + CLI detect。

#### Overall Impression

结构清晰，「打开即写」路径成立。最大机会：去掉入场编排与 overused display 字体，让日光金更干净、更不「AI 默认脸」。

#### What's Working

1. **状态诚实**：保存中/已保存/失败有文案，失败可重试；致命 DB 错误阻断编辑。
2. **信息架构克制**：一级分组 + 系统入口，符合 PRODUCT「结构克制」。
3. **触控与焦点**：`--tap`/`--tap-mobile`、`:focus-visible`、reduced-motion 已有。

#### Priority Issues

1. **[P1] 整页入场动画**
   - **What**: `.app-shell` 的 `shell-in`、`.note-editor`/`.empty-state` 的 `editor-in` 在加载时位移淡入。
   - **Why**: Product register 禁止编排式 page-load；用户要的是立刻进入任务。
   - **Fix**: 删除入场 keyframes；保留 hover/菜单/抽屉等状态过渡。
   - **Suggested command**: `$impeccable polish` / `$impeccable quieter`

2. **[P1] Display 字体用于 UI 文案**
   - **What**: loading 文案使用 `--font-display`（Fraunces）。
   - **Why**: Display-Is-Not-UI；工具文案应冷静。
   - **Fix**: loading 改 body 字体；display 仅保留笔记标题/空状态标题/对话框标题。
   - **Suggested command**: `$impeccable typeset`

3. **[P1] Overused display face (Fraunces)**
   - **What**: detector 标记 Fraunces 过度使用。
   - **Why**: 削弱「安静书桌」独特性，易被认作 AI 默认。
   - **Fix**: 换 Source Serif 4 + Noto Serif SC；保留衬线层次。
   - **Suggested command**: `$impeccable typeset`

4. **[P2] 侧栏分区全大写宽字距标签**
   - **What**: `.sidebar__section-label` uppercase + letter-spacing 0.08em。
   - **Why**: 接近 AI eyebrow 语法；在工具 UI 里略造作。
   - **Fix**: 取消 uppercase，字距收回 0.02em，字重保留。
   - **Suggested command**: `$impeccable quieter`

5. **[P2] 菜单 border+宽阴影**
   - **What**: `.menu__panel` 同时 1px border 与 blur 较大的 drop shadow。
   - **Why**: ghost-card 倾向；浮层过重。
   - **Fix**: 保留 border，阴影改为 ≤8px blur 的 soft。
   - **Suggested command**: `$impeccable polish`

6. **[P2] 帮助可发现性弱**
   - **What**: 快捷键存在但界面不可见。
   - **Why**: 效率用户发现成本高。
   - **Fix**: 侧栏 footer 或数据提示旁补一行快捷键说明（可选）。
   - **Suggested command**: `$impeccable clarify` / `$impeccable harden`

#### Persona Red Flags

**Alex（Power User / 快速随手记）**

- 快捷键可用但不可见；会怀疑「没有」。
- 侧栏分组+笔记双列表滚动区分裂，长列表时切换成本高。

**Jordan（First-Timer / 隐私敏感个人）**

- 空状态 CTA 清楚，首次路径好。
- 「数据保存在此浏览器」在 footer 偏弱，可能错过本地风险。

**Riley（移动端单手）**

- 移动抽屉与 44px tap 基本合格。
- 笔记行右侧 ⋯ 与标题并列，窄屏易误触。

- `text-wrap: balance` 未用于标题。

- 日光金是否应再降饱和，避免任何「手帐感」残留？
