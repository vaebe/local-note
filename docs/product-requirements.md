# Local Note 产品需求文档

## 1. 文档信息

- 产品名称：Local Note
- 产品形态：浏览器端在线记事本
- 文档版本：v1.0
- 当前阶段：MVP
- 数据方案：本地优先，使用 IndexedDB 持久化

## 2. 产品概述

Local Note 是一款极简、现代化的在线记事本。用户无需注册即可在浏览器中创建、整理和编辑笔记，所有数据默认保存在当前设备的 IndexedDB 中。

产品聚焦三件事：快速记录、清晰归类、安心保存。MVP 不引入账号、云同步和复杂富文本能力，尽量降低使用与维护成本。

## 3. 产品目标

### 3.1 核心目标

- 打开页面后可以立即开始记录。
- 通过可展开、收起的侧边栏快速定位分组和笔记。
- 分组仅支持一级，结构直观，避免目录层级带来的整理负担。
- 编辑内容自动保存，刷新或重新打开页面后数据仍然存在。
- 在桌面端与移动端均保持简洁、顺畅的使用体验。

### 3.2 非目标

以下能力不纳入 MVP：

- 用户注册、登录与多端云同步。
- 多人协作、分享和权限管理。
- Markdown 实时预览或复杂富文本排版。
- 图片、附件、音视频上传。
- 标签、全文搜索、版本历史与回收站。
- IndexedDB 数据的跨浏览器、跨设备自动迁移。

## 4. 目标用户与典型场景

### 4.1 目标用户

- 希望快速记录临时想法、待办和资料的个人用户。
- 注重隐私，希望内容仅保存在本机浏览器中的用户。
- 不需要复杂知识库功能，偏好轻量工具的用户。

### 4.2 典型场景

1. 用户首次进入应用，直接创建一篇笔记并输入内容。
2. 用户创建“工作”分组，并将相关笔记整理到该分组中。
3. 用户收起暂时不关注的目录，减少侧边栏干扰。
4. 用户编辑笔记后直接关闭页面，再次打开时继续编辑。
5. 用户在窄屏设备上打开侧边栏选择笔记，选中后回到编辑区。

## 5. 信息架构

### 5.1 层级规则

分组仅支持一级：

```text
全部笔记
└─ 一级分组（含默认分组）
   └─ 笔记
```

- 分组只能直接包含笔记，不能包含子分组。
- 笔记不计入分组层级。
- 不提供独立的「未分组」系统入口；笔记归入默认分组或用户创建的分组。
- 「全部笔记」为系统入口，不允许删除或重命名。

### 5.2 页面结构

```text
┌─────────────────────────────────────────────────────────┐
│ 侧边栏                         │ 编辑区                  │
│                               │                         │
│ Local Note              [＋]  │ 笔记标题                │
│ 全部笔记                      │ 更新时间                │
│ 分组                          │                         │
│ ▾ 工作                    [＋] │ 正文输入区域            │
│                               │                         │
│   · 周报                      │                         │
│ ▸ 生活                        │                         │
│                               │                         │
│ [新建分组]                    │               已保存    │
└─────────────────────────────────────────────────────────┘
```

桌面端采用左右双栏结构；移动端侧边栏作为抽屉覆盖显示，选择笔记后自动关闭。

## 6. 功能需求

### 6.1 侧边栏

- 展示产品名称、系统入口、分组树和笔记列表。
- 每个含有内容的分组提供展开/收起按钮。
- 展开状态应本地持久化，重新打开应用后尽量恢复上次状态。
- 当前选中的笔记需有明确但克制的高亮状态。
- 笔记按 `updatedAt` 倒序排列，最近编辑的笔记优先。
- 侧边栏支持整体收起与展开；桌面端收起后保留唤起按钮。
- 空分组仍需展示，并允许在其中新建笔记。

### 6.2 分组管理

- 支持创建、重命名和删除分组。
- 创建分组时，名称默认使用“新建分组”并立即进入重命名状态。
- 分组下不提供“新建子分组”入口。
- 同一父级下分组名称不可完全重复；保存前去除首尾空格。
- 分组名称为空时不可提交，最大长度为 40 个字符。
- 删除空分组时需要二次确认。
- 删除非空分组时需要说明影响，并提供两种选择：
  - 删除分组，将其中笔记移动到“未分组”。
  - 取消操作。
- MVP 不提供级联永久删除笔记，减少误操作风险。

### 6.3 笔记管理

- 支持新建、编辑、重命名和删除笔记。
- 新建笔记默认标题为“无标题笔记”，正文为空，并自动聚焦标题或正文。
- 标题最大长度为 120 个字符，正文使用纯文本，长度不做产品级硬限制。
- 用户可以将笔记移动到任意分组或“未分组”。
- 删除笔记前需要二次确认；MVP 删除后不可恢复。
- 当当前笔记被删除后，优先打开同分组中的下一篇笔记；若无笔记则展示空状态。

### 6.4 编辑与自动保存

- 编辑区包含标题、更新时间、正文和保存状态。
- 标题和正文变更后自动保存，不设置手动保存按钮。
- 输入停止 500 毫秒后执行防抖保存；页面失焦或关闭前应立即尝试保存未提交内容。
- 保存状态包括：“保存中”“已保存”“保存失败”。
- 保存失败时保留当前输入，不清空编辑区，并提供“重试”操作。
- 多次快速输入只更新同一条笔记记录，不产生历史副本。
- 未选中笔记时展示引导空状态，并提供“新建笔记”按钮。

### 6.5 首次使用与空状态

- 首次进入时不强制创建示例数据。
- 页面中央展示简短说明和“新建第一篇笔记”主按钮。
- 分组为空、笔记为空、无选中笔记时分别提供符合上下文的操作引导。
- 若浏览器不支持 IndexedDB，展示阻断式说明，不允许用户在无法保存的情况下继续编辑。

### 6.6 键盘与基础快捷操作

- `Ctrl/Cmd + N`：在当前分组中新建笔记。
- `Ctrl/Cmd + Shift + N`：新建分组。
- `Ctrl/Cmd + B`：展开或收起侧边栏。
- 快捷键触发时不得覆盖浏览器或输入框中的关键文本编辑行为。

## 7. 数据设计

### 7.1 IndexedDB 结构

数据库建议命名为 `local-note-db`，初始版本为 `1`。

#### `groups` 对象仓库

| 字段        | 类型   | 说明                           |
| ----------- | ------ | ------------------------------ |
| `id`        | string | UUID，主键                     |
| `name`      | string | 分组名称                       |
| `order`     | number | 同级排序值，为后续拖拽排序预留 |
| `createdAt` | number | Unix 毫秒时间戳                |
| `updatedAt` | number | Unix 毫秒时间戳                |

建议索引：`order`。

#### `notes` 对象仓库

| 字段        | 类型           | 说明              |
| ----------- | -------------- | ----------------- |
| `id`        | string         | UUID，主键        |
| `groupId`   | string \| null | `null` 表示未分组 |
| `title`     | string         | 笔记标题          |
| `content`   | string         | 纯文本正文        |
| `createdAt` | number         | Unix 毫秒时间戳   |
| `updatedAt` | number         | Unix 毫秒时间戳   |

建议索引：`groupId`、`updatedAt`、`[groupId+updatedAt]`。

#### `settings` 对象仓库

| 字段    | 类型    | 说明       |
| ------- | ------- | ---------- |
| `key`   | string  | 设置项主键 |
| `value` | unknown | 设置值     |

首期可保存：侧边栏是否收起、已展开分组 ID、最后打开的笔记 ID、主题偏好。

### 7.2 数据约束

- 删除分组与迁移笔记应在同一个 IndexedDB 事务中完成。
- 更新笔记内容时同步更新 `updatedAt`。
- 应提供数据库版本升级入口，后续通过 `onupgradeneeded` 执行迁移。

### 7.3 隐私与数据提示

- 页面需明确提示：数据仅保存在当前浏览器中，不会自动同步。
- 清除站点数据、使用隐私浏览模式或浏览器回收存储空间可能导致数据丢失。
- MVP 可在“关于/设置”中展示说明；导入导出作为后续版本优先能力。

## 8. 视觉与交互规范

### 8.1 设计原则

- 极简：界面仅保留记录与整理所需元素。
- 现代：使用充足留白、清晰层级、轻量圆角与细腻状态反馈。
- 克制：少用强边框和大面积高饱和颜色，不让导航抢夺内容注意力。
- 一致：创建、重命名、移动和删除操作采用统一的菜单与反馈模式。

### 8.2 视觉建议

- 主背景使用中性浅色，编辑区与侧边栏通过轻微色差或细分隔线区分。
- 正文字号建议 16px，行高 1.7；标题字号建议 28–32px。
- 侧边栏桌面端宽度建议 280px，可收起；内容区最大阅读宽度建议 760–860px。
- 圆角建议 8–12px；阴影仅用于抽屉、菜单和弹窗等浮层。
- 主色只用于选中态、主按钮和焦点环。
- 动效时长建议 150–220ms，并尊重 `prefers-reduced-motion`。
- 支持浅色与深色模式可作为增强项；MVP 至少保证浅色模式完整可用。

### 8.3 可访问性

- 所有图标按钮提供可读标签或 `aria-label`。
- 展开按钮使用 `aria-expanded` 表达状态。
- 键盘可以访问侧边栏、菜单、对话框和编辑区。
- 焦点状态清晰可见，弹窗关闭后焦点返回触发元素。
- 正文与背景对比度至少满足 WCAG AA。
- 可点击区域建议不小于 40 × 40px，移动端不小于 44 × 44px。

## 9. 响应式行为

| 视口         | 布局与行为                                       |
| ------------ | ------------------------------------------------ |
| `>= 1024px`  | 固定双栏；侧边栏默认展开，可手动收起             |
| `768–1023px` | 双栏或覆盖式侧边栏，根据可用宽度自适应           |
| `< 768px`    | 单栏编辑区；侧边栏以全高抽屉打开，选择笔记后关闭 |

移动端需处理软键盘遮挡、正文滚动和安全区域，不使用仅依赖悬停的交互。

## 10. 异常与边界情况

- IndexedDB 初始化失败：展示原因和重试入口。
- 存储空间不足：提示保存失败，并建议用户复制当前内容后清理空间。
- 最后打开的笔记已不存在：回退到最近更新的笔记或空状态。
- 数据存在孤立引用：将对应笔记视为“未分组”，避免内容不可见。
- 两个标签页同时编辑同一笔记：MVP 采用最后写入覆盖，并可通过 `BroadcastChannel` 提示其他标签页数据已更新。
- 页面刷新或关闭：立即提交防抖队列中尚未保存的编辑。
- 超长标题：输入达到 120 个字符后停止继续录入并给出轻提示。

## 11. 非功能要求

- 首屏在常规桌面环境下应快速可交互，MVP 目标为 2 秒内。
- 普通输入和目录展开反馈应即时，目标响应时间低于 100ms。
- 支持最近两个主要版本的 Chrome、Edge、Firefox 和 Safari。
- 应用无需后端即可完成 MVP 核心流程。
- 数据访问逻辑与界面组件解耦，便于测试和后续引入导入导出或同步。
- 对 IndexedDB 写入失败、事务中断和版本升级失败提供可见反馈。

## 12. MVP 验收标准

### 12.1 核心流程

- [ ] 首次进入可以创建笔记，输入标题和正文后自动保存。
- [ ] 刷新页面后，已创建的笔记及内容完整恢复。
- [ ] 可以创建一级分组，界面不提供创建子分组的入口。
- [ ] 可以在任意允许的位置新建笔记，并将笔记移动到其他分组。
- [ ] 侧边栏分组可以独立展开与收起，状态在刷新后恢复。
- [ ] 可以重命名和删除分组，删除非空分组时笔记安全移动到“未分组”。
- [ ] 可以删除笔记，删除前出现确认提示。
- [ ] IndexedDB 保存失败时界面显示错误，且当前输入不会丢失。

### 12.2 体验与质量

- [ ] 桌面端和移动端均可完成创建、编辑、整理和删除流程。
- [ ] 所有核心功能可使用键盘操作，焦点状态清晰可见。
- [ ] 页面不存在横向溢出，移动端软键盘不会遮挡主要编辑区域。
- [ ] 目录展开、切换笔记和输入过程无明显卡顿。
- [ ] 清空浏览器站点数据的风险说明可被用户找到。

## 13. 后续迭代方向

建议按以下优先级评估：

1. JSON/Markdown 导入与导出，降低本地数据丢失风险。
2. 标题与正文全文搜索。
3. 回收站与笔记版本历史。
4. 分组和笔记拖拽排序。
5. Markdown、主题切换与更多编辑体验。
6. 可选账号体系、端到端加密与多端同步。
